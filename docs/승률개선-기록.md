# 승률 개선 기록

매일 새벽 6시(KST) 자동 점검이 이 파일을 읽고, 작업 후 맨 아래 **기록**에 추가한다.
세션은 매번 새로 시작하므로 **이 파일이 유일한 연속성**이다. 여기 없는 것은 없던 일이다.

---

## 0. 목표를 정확히

**승률을 올리되, 기대값(거래당 평균 손익)을 떨어뜨리지 않는다.**

> ⚠️ 승률만 쫓으면 반드시 실패한다. 익절 +0.5% / 손절 -10% 로 두면 승률 90% 가
> 나오지만 기대값은 마이너스다. 승률이 올라도 `평균수익률 × 거래횟수` 가 줄면
> 그 변경은 **되돌린다**. 두 숫자를 항상 같이 본다.

판단 기준 (백테스트 기준, 왕복 비용 차감 후):
- 승률 ↑ 이고 평균수익률 ≥ 기존 → 채택
- 승률 ↑ 이지만 평균수익률 ↓ → **기각** (기록에 남기고 다시 시도하지 않는다)
- 표본 100건 미만 → 판단 보류. 표본을 늘려서 다시 본다

## 1. 반드시 지킬 것

이 프로그램은 **실제 돈으로 주문을 낸다.** 아래는 예외 없다.

1. **빌드가 초록불이 아니면 main 에 올리지 않는다.** 폰이 main 을 자동으로 받아간다.
2. **매매 동작을 바꾸는 변경은 기본값을 끔(빈 값)으로 둔다.** 사용자가 화면에서
   켜야 적용되게 한다. 예외: 명백한 버그 수정(손실을 막는 방향)만 기본 적용.
3. **매수 금액·포지션 수 설정은 건드리지 않는다.** 돈의 크기는 사용자만 정한다.
4. **보유 중인 종목의 매도 조건을 말없이 바꾸지 않는다.** 이미 들고 있는 종목은
   살 때의 판단을 따른다.
5. **되돌릴 수 있게 한다.** 한 번에 한 가지만 바꾸고, 무엇을 왜 바꿨는지 여기 남긴다.
6. **검증 없이 '좋아 보이는' 변경을 넣지 않는다.** 근거는 백테스트 숫자 또는
   코드에서 실제로 확인한 결함이어야 한다.

### 하지 않는 것

시장 조작, 미공개 정보 이용, 증권사·거래소 API 약관 위반(호출 한도 우회, 다중 계정
등). 계좌 정지와 법적 문제로 직결되고, 그렇게 얻은 승률은 유지되지도 않는다.

## 2. 무엇으로 검증하는가

⚠️ **자동 점검 세션은 사용자의 폰이나 증권사 계좌에 접근할 수 없다.** 실거래
결과(engine_state.db)와 한투·키움 시세는 사용자의 API 키가 있어야 해서 볼 수 없다.
쓸 수 있는 것은 이것뿐이다:

| 수단 | 쓸 수 있는가 | 비고 |
|---|---|---|
| **업비트 공개 시세** | **가능** | 인증 불필요. 원화마켓 일봉/분봉을 실제로 받아 백테스트 가능 |
| 51개 매매법 코드 | 가능 | **세 엔진이 같은 코드를 공유한다** — 업비트 데이터로 검증한 결과가 주식에도 대체로 적용된다 |
| 엔진 로직(진입·청산·리스크) | 가능 | 코드를 읽고 결함을 찾는다 |
| 한투/키움 시세 | 불가 | 사용자 API 키 필요 |
| 사용자의 실거래 결과 | 불가 | 폰 안에만 있다 |

그래서 검증은 **업비트 실데이터 백테스트 + 코드 분석** 두 가지로 한다.
주식에만 해당하는 변경(장 시간, 상하한가 등)은 백테스트로 확인할 수 없으므로
**기본값 끔**으로 넣고 사용자가 판단하게 한다.

### 도구 제약 — 이 세션에는 GitHub MCP 도구가 없다

정기 실행 세션은 `mcp__github__*` 도구 없이 뜬다. 대신 이렇게 한다.

| 하고 싶은 것 | 방법 |
|---|---|
| 빌드 띄우기 | **작업 브랜치에 push 하면 자동으로 돈다** (`claude/**` 도 빌드 대상) |
| 빌드 결과 확인 | `curl -sS "https://api.github.com/repos/tlsgusdlf33/autotrader/actions/runs?branch=<브랜치>&per_page=1"` — 공개 저장소라 **인증 없이** 된다 |
| 빌드 로그 보기 | 같은 API 의 `jobs` 엔드포인트. 또는 실패 시 `logs_url` |
| main 에 반영 | 브랜치에서 초록불 확인 후 `git checkout main && git merge --ff-only <브랜치> && git push origin main` |

⚠️ **순서를 지켜라.** main 에 push 하는 순간 릴리스가 발행되고 폰이 받아간다.
반드시 작업 브랜치에서 먼저 빌드를 통과시킨 뒤 main 으로 옮긴다.

## 4. 후보 목록 (아직 안 해본 것)

위에서부터 근거가 확실한 순서다. 매일 **하나씩** 집어서 검증하고, 결과를 기록한다.

1. ~~**시장 상태 필터**~~ — **2026-09-20 완료.** 단, BTC 이동평균이 아니라
   **시장 폭**(전체 중 자기 20일선 위 비율)이 훨씬 잘 맞았다. 아래 기록 참고.
2. **매매법별 파라미터 튜닝** — 익절/손절 비율을 매매법마다 백테스트로 찾는다.
   ⚠️ 과최적화 위험이 크다. 앞 구간으로 찾고 뒤 구간으로 확인(walk-forward)한다.
3. **시간대 필터** — 장 초반/막판 변동이 큰 구간을 피한다. 분봉 필요.
4. **동시 보유 상관관계 제한** — 같은 섹터·같은 테마를 여러 개 들지 않는다.
   한 번에 같이 빠져서 손실이 겹친다.
5. **연속 손실 시 자동 중단** — N번 연속 손절이면 그날은 신규 매수를 멈춘다.
6. **진입 가격 개선** — 신호 즉시 시장가 대신 조금 유리한 지정가를 잠깐 걸어본다.
   체결 실패 위험과 맞바꾸는 것이라 신중히.
7. **매매법 조합 검증** — 두 매매법이 동시에 신호를 낼 때 승률이 더 높은지 확인.
   ⚠️ 종목 갈아타기는 5번 기각 목록 참고 — 다시 시도하지 말 것.
8. **백테스트 표본 확대** — 종목 수·기간을 늘려 승률 추정의 신뢰도를 올린다.
