# AutoTrader

`AutoTrader.zip` 하나만 올려두면 GitHub Actions 가 알아서 풀어서 APK 를 만듭니다.
자세한 사용법은 zip 안의 `APK만들기.md` 를 보세요.

---

## 고쳐서 다시 깔아도 키·매매법이 남습니다

예전에는 새 APK 를 깔려면 **앱을 지워야** 했습니다. 지우는 순간

- 입력해 둔 API 키·계좌번호
- 엔진 거래 기록(`engine_state.db`) — **어떤 종목을 어떤 매매법으로 샀는지**

가 앱 폴더와 함께 전부 사라졌습니다. 그래서 다시 깔 때마다 키를 새로 넣어야
했고, 계좌에 남아 있던 종목은 '모르는 종목'이 되어 기본 매매법(#16)으로 다시
주워담겼습니다.

원인은 **서명 키**였습니다. 안드로이드는 같은 키로 서명된 APK 만 기존 앱 위에
덮어 설치하게 해주는데, gradle 이 자동으로 만드는 debug 키는 빌드하는 기계마다
새로 생깁니다. GitHub Actions 는 매번 새 기계에서 돌기 때문에, 빌드할 때마다
서명이 달라졌습니다.

지금은 이렇게 동작합니다.

| | 하는 일 |
|---|---|
| `app/autotrader.jks` | 저장소에 함께 둔 고정 서명 키. 항상 같은 서명이라 **덮어 설치**가 됩니다 |
| `APP_VERSION_CODE` | 빌드할 때마다 GitHub 실행 번호가 들어갑니다. 번호가 줄면 설치가 거부됩니다 |
| 자동 백업 | 키와 거래 기록을 암호화해 **다운로드/AutoTrader** 등 세 곳에 남기고, 새로 깔면 스스로 되살립니다 |
| 매매법 되살리기 | 추적이 끊긴 종목을 다시 주워담을 때 **지난 매수 기록**에서 매매법을 찾습니다 |

### ⚠️ 딱 한 번은 지우고 깔아야 합니다

이번 APK 는 예전 APK 와 서명이 다릅니다 — 예전 건 빌드할 때마다 서명이
달랐으니 어차피 맞출 수가 없습니다. **이번 한 번만** 앱을 지우고 새로 깔면서
키를 다시 넣어주세요. 그 다음부터는 새 APK 를 그냥 덮어 설치할 수 있고,
키도 매매법 기록도 그대로 이어집니다.

### 서명 키가 저장소에 있어도 되나요

이 키는 비밀이 아닙니다(구글의 기본 debug 키도 공개되어 있습니다). 본인 폰에
직접 설치해 쓰는 앱이라 이렇게 둡니다. 다만 **Google Play 에는 이 키로 올리면
안 됩니다** — 그때는 별도 키를 만들어 GitHub Secrets 에 넣어야 합니다.

백업 파일 쪽은 다릅니다. API 키가 들어가므로 AES-GCM 으로 암호화하고, 열쇠는
그 기기(ANDROID_ID)에 묶습니다. 파일만 빼가도 다른 기기에서는 풀 수 없습니다.
