# AutoTrader

`AutoTrader.zip` 하나만 올려두면 GitHub Actions 가 알아서 풀어서 APK 를 만듭니다.
자세한 사용법은 zip 안의 `APK만들기.md` 를 보세요.

---

## 고쳐서 다시 깔아도 키·매매법이 남습니다

예전에는 새 APK 를 깔려면 **앱을 지워야** 했습니다. 지우는 순간

- 입력해 둔 API 키·계좌번호
- 엔진 거래 기록(`engine_state.db`) — **어떤 종목을 어떤 매매법으로 샀는지**

가 앱 폴더와 함께 전부 사라졌습니다. 그래서 다시 깔 때마다 키를 새로 넣어야
했고, 계좌에 남아 있던 종목은 '모르는 종목'이 되어 기본 매매법(#16)으로 다시
주워담겼습니다.

원인은 **서명 키**였습니다. 안드로이드는 같은 키로 서명된 APK 만 기존 앱 위에
덮어 설치하게 해주는데, gradle 이 자동으로 만드는 debug 키는 빌드하는 기계마다
새로 생깁니다. GitHub Actions 는 매번 새 기계에서 돌기 때문에, 빌드할 때마다
서명이 달라졌습니다.

지금은 이렇게 동작합니다.

| | 하는 일 |
|---|---|
| `app/autotrader.jks` | 저장소에 함께 둔 고정 서명 키. 항상 같은 서명이라 **덮어 설치**가 됩니다 |
| `APP_VERSION_CODE` | 빌드할 때마다 GitHub 실행 번호가 들어갑니다. 번호가 줄면 설치가 거부됩니다 |
| 자동 백업 | 키와 거래 기록을 암호화해 **다운로드/AutoTrader** 등 세 곳에 남기고, 새로 깔면 스스로 되살립니다 |
| 매매법 되살리기 | 추적이 끊긴 종목을 다시 주워담을 때 **지난 매수 기록**에서 매매법을 찾습니다 |

### ⚠️ 딱 한 번은 지우고 깔아야 합니다

이번 APK 는 예전 APK 와 서명이 다릅니다 — 예전 건 빌드할 때마다 서명이
달랐으니 어차피 맞출 수가 없습니다. **이번 한 번만** 앱을 지우고 새로 깔면서
키를 다시 넣어주세요. 그 다음부터는 새 APK 를 그냥 덮어 설치할 수 있고,
키도 매매법 기록도 그대로 이어집니다.

### 서명 키가 저장소에 있어도 되나요

이 키는 비밀이 아닙니다(구글의 기본 debug 키도 공개되어 있습니다). 본인 폰에
직접 설치해 쓰는 앱이라 이렇게 둡니다. 다만 **Google Play 에는 이 키로 올리면
안 됩니다** — 그때는 별도 키를 만들어 GitHub Secrets 에 넣어야 합니다.

백업 파일 쪽은 다릅니다. API 키가 들어가므로 AES-GCM 으로 암호화하고, 열쇠는
그 기기(ANDROID_ID)에 묶습니다. 파일만 빼가도 다른 기기에서는 풀 수 없습니다.

## 매매법 백테스트

대시보드 안의 **매매법 백테스트** 카드에서 **백테스트 실행**을 누르면, 이미 받아둔
일봉으로 51개 매매법을 과거에 대입해 매매법마다 몇 번 신호가 났고 그중 몇 번
이겼는지 계산합니다.

표시 순서는 **거래가 많은 순 → 승률 높은 순**입니다(버튼으로 승률 우선으로 전환).
거래 횟수를 먼저 보는 이유는, 2번 신호가 나서 2번 맞은 승률 100%는 실력이 아니라
우연이기 때문입니다. 20건 미만인 승률은 흐리게 표시합니다.

| | |
|---|---|
| 데이터 | 엔진이 쌓아둔 일봉 캐시. **증권사에 새로 조회하지 않습니다** (업비트는 인증 불필요한 시세 조회 사용) |
| 매수 | 신호 **다음 날 시가** — 같은 날 종가로 계산하면 미래를 미리 본 셈이 됩니다 |
| 매도 | 그 매매법 자신의 매도·손절 조건 (안 걸리면 30거래일 뒤 강제 청산) |
| 비용 | 왕복 수수료·세금·슬리피지를 미리 뺍니다 (주식 0.25%, 업비트 0.1%) |
| 제외 | 분봉·호가가 필요한 12개(51번 포함)는 일봉으로 재현할 수 없어 측정하지 않습니다 |

끝나면 매수 우선순위가 승률 높은 순으로 다시 세워집니다(재시작 불필요).
매매법을 실제로 빼려면 `.env`에 `STRATEGY_MIN_WIN_RATE_PCT` 같은 기준을 주세요.

⚠️ 매매 엔진과 같은 프로세스에서 돌아서 그동안 손절 감시가 조금 느려집니다 —
**장 마감 후**에 돌리는 것을 권합니다. 진행률·남은 시간이 표시되고 중단할 수 있습니다.

## 수익률 개선 설정

대시보드 **매매 설정**에 있습니다. **전부 기본이 '비어 있음 = 끔'** 이라, 넣지 않으면
예전과 똑같이 동작합니다.

| | 권장 | 하는 일 |
|---|---|---|
| ⚑ 전체 안전 손절(%) | **3~5** | 매매법이 뭐든 이 선에서 자릅니다. 51개 중 33개는 손절선이 차트 모양 기준이라 -10%까지 끌려갑니다 |
| ⚑ 전체 트레일링(%) | 5~8 | 고점 대비 이만큼 밀리면 익절 |
| ⚑ 최대 보유일 | 5~10 | 무기한 묶인 돈을 풀어줍니다 |
| ★ 승률 하한(%) 미만 제외 | 45 | 백테스트 승률이 낮은 매매법을 매수에서 뺍니다 |
| ★ 익절 시 먼저 팔 비율(%) | 50 | 익절 신호에서 절반만 팔고 나머지는 들고 갑니다 |
| ★ 손실 종목 재매수 금지(일) | 3 | 손실로 판 종목을 이 기간 다시 사지 않습니다 |
| ★ 주워담기 기본 매매법 # | 35 | 기록 없는 보유 종목에 붙일 매매법 |

`[51번]`이 붙은 익절·손절은 **51번 매매법만** 씁니다. 나머지 50개는 각자의 조건으로
판단합니다 — 화면에 표시를 갈라둔 이유입니다.

**주워담기 기본값을 #16 → #35 로 바꿨습니다.** #16은 매도가 `당일 시가 +3%`,
손절이 `전일 저가 붕괴`라 진입가를 전혀 보지 않습니다. #35는 익절 +8% / 손절 -4%를
둘 다 진입가 기준으로 봅니다. 바뀌는 것은 앞으로 주워담는 종목뿐이고, 이미 #16으로
기록된 보유 종목은 그대로입니다(보유 종목 줄의 `매매법 #16 ✎`으로 직접 바꿀 수 있습니다).
